Settings validation uses the authenticated model catalog without consuming a Codex turn, and account fallback chat reuses only the latest bounded persisted conversation messages.
- Release baseline: PageDock 0.9.0; the independent side-chat popup is a source-level feature pending a release installer
- Build status: documentation, lint, TypeScript, 133 tests plus 1 intentionally skipped integration test, production build, and a separate-output Windows Electron packaging artifact passed. The isolated audit artifact is `dist-sidechat-audit\win-unpacked\PageDock.exe`; it does not replace the existing `dist` output or include user data. - Backup: v2 export/import; v1 import retained
- Knowledge MVP: draft-safe multi-file immutable inbox, device-local recursive memo-folder capture, local long-note split previews, next-ten/single-flight ChatGPT-OAuth-only proposals, non-destructive authentication errors, cancellation/timeout and first-error stop, lazy bounded review rendering, direct user wiki revisions, conflict resolution notes, recoverable revision trash, storage-size visibility, verified v1 rollback backup, stale-update protection, restorable topic history, current-wiki Markdown export, and additive provenance-gated Reader/AI promotion (`.annot/knowledge-store.json` format 2 with v1 normalization). A source is classed as literature claim, work observation, personal hypothesis, or AI inference; no age-based truth/expiry state exists. Human review attention changes neither body nor revision.
- Windows artifact: the existing `PageDock-Setup-0.9.0.exe` baseline is not refreshed for the side-chat feature; use the isolated unpacked smoke executable above for this working-tree build
- Supported platform: Windows 10/11 x64 only. The former experimental Apple Silicon port and its old CI artifacts are unsupported historical work and must not be rebuilt or distributed.
- PDF study loop: semantic sidecar highlights (`important`, `concept`, `memorize`, `question`, `unclear`), user-controlled unresolved/resolved state, selection-to-AI source anchors, PDF return markers, portable page/scroll resume, current-PDF source-anchored basic/Cloze recall cards, optional source-anchored work classifications (`finding`, `verify`, `discuss`, `try`), and one-rectangle visual records (`figure`, `table`, `equation`, `process_condition`, `custom`) are additive to existing `.annot` sidecars, sessions, and paper metadata. The Reader keeps top-level selection actions to important / needs-understanding / note / ask-AI, with lower-frequency semantic, review, work, and translation actions in More. Selection actions anchor immediately below the selected source and flip above only at the viewport edge; amber unresolved marks retain an app-specific boundary distinct from live OS selection. Its responsive `기록` right overlay drawer preserves the PDF width and position while separating `읽기·학습`, `업무`, and `영역`. A visual-record editor is a keyboard-contained source-visible right sheet, so the original figure/table remains visible while the user assigns a type and optional memo. A visual record preserves only `documentId`, page-relative normalized geometry, user kind/memo, and timestamps: no crop, thumbnail, OCR, or AI output becomes a second source. `workDoneAt` is independent of study `resolvedAt`. The Windows Reader uses PDF.js's stable main-thread canvas path rather than worker-side OffscreenCanvas/image-decoder acceleration, and remounts the document once after a transient page-render failure; this keeps valid PDFs with problematic embedded images/fonts visible without altering their data. A structured current-PDF Evidence Brief previews Finding/open/completed work evidence (plus clearly non-exported learning context), and Library rows derive resume/unresolved/open-work counts from existing metadata and sidecars. Cloze, work evidence, and visual records are local-first and work without AI/Python. SQLite schema and backup manifest remain unchanged.
- Secondary AI perspective: a bounded PDF selection question can be saved locally and open the visible Settings-managed `DeepSeek 웹 보조` flow without a primary AI answer or provider login. PageDock previews only the exact stored selection and original user question, copies it on an explicit click, and opens an isolated Electron web partition where the user logs in, pastes, and sends directly. A user-pasted reply is stored additively on the persisted user anchor when no primary exists, or on the linked assistant when one exists, as `deepseek / web-manual / user-paste`, with a prompt SHA-256 receipt and timestamps. The in-app view is single-answer until a real primary answer exists, then comparison remains descriptive only: it creates no winner, consensus, automatic resolution, knowledge item, card, SQLite schema, or backup-manifest change. PageDock never reads DeepSeek passwords, cookies, tokens, or web-page conversation content; clearing the dedicated web session leaves Library and imported records intact.
- Independent side-chat: the popup keeps PageDock AI records in the additive `sidechat` namespace, with explicit source handoff and separate web-provider tabs. A new typed question wins over an older saved question when preparing a web prompt, and local web-answer/model drafts are keyed by session, question, and provider so tab/session/popup re-entry does not cross tasks. Native embedded web views are hidden while PageDock overlays are open and stale provider loads cannot reveal an inactive tab. These convenience drafts are device-local and are not part of portable backups.
- Reader feedback polish: successful learning/work/visual saves keep the reader in place but provide `기록에서 보기` for the corresponding record tab. The PDF chat composer exposes the exact per-turn source scope and declares that personal work records and Knowledge notes are not auto-sent; the lightweight Library session marker restores the active Reader document in the same desktop session without replacing portable reading resume.
- Reader hierarchy polish: the persistent Reader controls remain page/search/view/zoom/mark/visual-region capture, while `기록 보기` is a secondary document-tool action. Selection language is `중요 / 이해 필요 / AI 설명 / 메모`; an unresolved save can open the existing unresolved filter directly. Library is the compact primary navigation item; Research and Knowledge remain unchanged destinations behind `더보기` so they do not visually compete with reading. AI proposals are visibly distinct from reviewed current Knowledge without changing any storage or trust contract.
- Mobile Bridge: a user-selected, provider-neutral external folder can hold a read-only `PageDock-Mobile.pdf` for an explicit document-id Mobile Shelf, plus a minimal SHA-256 receipt. It projects labelled Reader records, anchored AI answers, recall cards, source-linked Knowledge topics, and in-memory visual-region renders without copying live Library files or storing crops. Automatic publication is opt-in and off by default; relevant projected changes remain visibly dirty, then coalesce after 90 seconds with a ten-minute automatic rate limit. A mismatched or externally removed mobile pair blocks automatic overwrite until the user takes an explicit action. Automatic portable v2 backups now validate a local partial ZIP before publishing it and may copy the same bytes to bridge `Backups/Auto`; local and bridge automatic retention are independently three, while bridge manual full backups include PDFs and are never pruned.
- UI calmness polish: the desktop surface uses a softer paper-neutral hierarchy, while important, needs-understanding, resolved, AI-reference, and real-error states now have distinct muted roles with text/icons rather than color alone. The selection bar is smaller, source-centered, and less likely to cover the next line; search empty states explain the next local action. Knowledge uses people-first labels such as `정리된 노트`, `바뀐 점`, `AI 초안 · 확인 전`, and `다시 볼 표시`; these are presentation-only changes and do not alter provenance, review, storage, or backup contracts.
- Re-entry and wording refinement: Library document rows now project existing resume page, unresolved count, and last-opened date. Its top `계속 읽기` card gives one primary Reader action; `다시 볼 것 N` is a smaller link that opens only the existing unresolved Reader filter for that PDF. The Reader record drawer exposes a direct explicit `이해 완료` action, while selection-time language remains `이해 필요`. Research/Knowledge copy keeps remote AI as a named optional action, while Settings visibly separates one-way phone reading from PageDock recovery backup. These are presentation and existing-sidecar/metadata projections only: no new dashboard, study state, automatic PDF opening, auto-card generation, sync, or backup-format change was added.
- Collapsed library rail: when the folder/file explorer is closed or temporarily compacted for reading/chat, the rail no longer rotates the `탐색기` label; it shows a stable folder icon and tooltip so the narrow state stays legible.

Known issues:

- KIPRIS Plus and EPO OPS support authenticated search; richer citation, family, and legal-event normalization remains planned. Manual number/URL/PDF and external provider links work without keys.
- Codex-assisted query expansion/reranking and robust author/year/patent-number extraction remain planned. Exact local FTS remains the offline fallback.
- Python-free restore currently holds archives up to 512MB in memory; larger archives require the prepared PDF/Python tool until a streaming Node extractor is added.
- Windows installer is not code-signed, so SmartScreen may warn.
- Next.js Turbopack still reports the known dynamic filesystem tracing warning for sidecar-backed Reader routes; the production build succeeds, but the trace should be narrowed in a later maintenance pass.
- WebView2 migration is deferred.
