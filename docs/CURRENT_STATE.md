## 0.9.3 visual Knowledge notes (2026-09-14)

PageDock 0.9.3 adds deliberate visual memory to the existing local Knowledge inbox: a user can keep one PNG/JPEG diagram, screenshot, or photo (up to 10 MB) alongside a short explanation. The binary is a verified content-addressed file under `.annot/knowledge-assets`; the format-2 Knowledge JSON stores only its hash, MIME, and byte count. The same image is stored once, but the same caption with another image remains a distinct note. Image bytes are never automatically sent to PageDock AI, Codex, DeepSeek, or a web provider. Existing portable v2 backup collection carries them as normal Library files, while the Mobile Bridge embeds them only for explicitly selected notes. SQLite schema 1, annotation-sidecar version 1, portable-backup manifest v2, and NAS snapshot protocol remain unchanged.

## 0.9.2 NAS safety snapshots (2026-09-13)

PageDock 0.9.2 adds an optional device-local NAS protection target without changing SQLite schema 1, annotation-sidecar version 1, or portable-backup manifest v2. A Windows-accessible target folder (typically a mapped Synology SMB share) receives only a locally completed and manifest-verified PDF-excluding portable ZIP. The target copy is written as a unique partial file, SHA-256 checked against the local source, then renamed into `PageDock-Backups/Auto`; fourteen successful target generations are kept independently. The target path and small success/failure state live only in `%APPDATA%\\PageDock\\backup-replica.json`; credentials, NAS URLs, Library data, and sync state are not stored. Automatic copying is off by default; an explicit `지금 보호 사본 만들기` can copy once without enabling it. NAS failure never delays a Reader save or makes a successful local backup fail. The active Library and all SQLite/sidecar/session work remain local, while NAS source PDFs are a separate archive/import concern.

0.9.2 verification (2026-09-13): `docs:check`, ESLint, TypeScript, full Vitest (33 passing files / 164 passing tests, one intentionally skipped file/test), production build, icon generation, and isolated Windows unpacked packaging passed. The final package server smoke exited 0. A separate isolated synthetic Library/package visual run opened the Reader and rendered a real synthetic PDF page with visible source text and shape; it used no user PDF or AI send. The final package differs from that visual package only by the corrected NAS/bridge retention wording. The production build retains seven pre-existing broad dynamic-filesystem tracing warnings around sidecar/Knowledge routes.
