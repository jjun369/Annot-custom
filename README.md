# PageDock

## 지원 환경

PageDock은 **Windows 10/11 x64 전용**입니다. macOS와 Linux 빌드·테스트·배포는 지원하지 않습니다.

개인 메모를 위키로 정리하는 기능은 [지식 정리 한국어 사용 설명서](./docs/KNOWLEDGE_USER_GUIDE_KO.md)를 참고하세요.

상단의 `?` 버튼 또는 `F1`을 누르면 현재 화면에 맞는 사용법과 문제 해결 팁을 볼 수 있습니다.

PageDock은 PDF를 한곳에 모아 읽고, 표시하고, 모르는 문장을 그 자리에서 선택적으로 AI에게 물으며, 원문 근거를 업무 판단·후속 확인으로 남긴 뒤 정확한 위치로 이어서 공부하는 Windows용 로컬 작업 공간입니다.

> 현재 버전은 지인 대상 초기 배포판입니다. 설치 파일은 아직 코드 서명되지 않았으므로 Windows SmartScreen 경고가 나타날 수 있습니다.

## 일반 사용자 설치

1. GitHub Releases에서 `PageDock-Setup-버전.exe`를 받습니다.
2. 설치 파일을 실행하고 기본 위치에 설치합니다.
3. PageDock의 첫 실행 안내를 따라 라이브러리와 선택적 AI 연결을 준비합니다.

사용자가 Node.js, npm, Python 명령어 또는 터미널을 직접 사용할 필요는 없습니다.

### 첫 실행에서 일어나는 일

- 새 사용자의 기본 라이브러리는 `문서\PageDock Library`입니다.
- 기존 `~/Annot` 라이브러리나 설정이 있으면 그대로 이어서 사용합니다.
- PDF를 추가하면 원본은 건드리지 않고 PageDock Library로 복사합니다.
- 같은 내용의 PDF는 SHA-256으로 감지해 중복 복사하지 않습니다.
- 파일명이나 폴더가 바뀌어도 안정적인 문서 ID와 SHA-256으로 메모·하이라이트·프로젝트 연결을 복구합니다.
- PDF 원본 주석 기능에 필요한 Python/PyMuPDF는 Windows의 공식 패키지 경로를 통해 자동 준비합니다.
- PDF 도구 준비는 선택 사항이며 첫 실행에서 `나중에`를 선택해도 기본 읽기와 메모를 사용할 수 있습니다.
- AI는 선택 사항입니다. 연결하지 않아도 PDF 읽기, 검색, 하이라이트와 메모를 사용할 수 있습니다.
- Codex 연결을 선택하면 OpenAI 공식 Windows 설치 스크립트와 브라우저 로그인 흐름을 사용합니다. OpenCodex 데스크톱 앱만 설치된 경우에는 같은 ChatGPT OAuth 로그인과 계정 연결을 사용해 standalone CLI 없이도 연결할 수 있습니다.

## 데이터와 백업

- PDF와 공부 기록은 설치 폴더가 아닌 PageDock Library에 저장됩니다.
- 앱을 삭제해도 라이브러리는 자동으로 삭제하지 않습니다.
- PDF를 제외한 연구 데이터는 하루 한 번 자동 백업하며 최근 3개를 유지합니다. 사용자가 내려받은 수동 전체 ZIP은 자동으로 지우지 않습니다. 리서치 DB는 이식 가능한 JSON으로 저장됩니다.
- 전체 ZIP 내보내기에는 PDF와 메모, 하이라이트, 복습 카드, 대화 기록이 포함됩니다.
- 로그인 토큰은 백업 파일에 포함하지 않습니다.
- ZIP 가져오기 전에는 PDF를 제외한 안전 백업을 자동으로 한 번 더 만듭니다. Python이 없어도 512MB 이하 백업은 복원할 수 있습니다.
- 기존 Annot 백업 형식과 내부 `.annot` 데이터는 호환성을 위해 계속 지원합니다.
- 설정에서 Google Drive·OneDrive·Dropbox 같은 별도 연결 폴더를 지정하면, 직접 고른 모바일 보관함의 공부 기록을 `PageDock-Mobile.pdf` 한 파일로 발행할 수 있습니다. 이는 읽기 전용 파생 사본이며 라이브러리 자체를 동기화하지 않습니다. 변경 후 자동 발행은 기본적으로 꺼져 있고, 필요할 때만 켜거나 직접 발행할 수 있습니다.
- 연결 폴더의 자동 백업도 최신 3개를 별도로 유지합니다. PDF가 포함된 수동 전체 백업은 `Backups/Manual`에 만들며 자동으로 삭제하지 않습니다.

## PDF 공부 루프

- PDF 문장을 선택하면 `중요` / `이해 필요` / `AI 설명` / `메모` 중 하나를 바로 고릅니다. `더보기`에는 개념·정의, 외울 것, 질문 표시, 복습·빈칸 카드, 업무 후속, 선택 영역 번역이 정리되어 있습니다. `질문으로 표시`는 미해결 학습 기록이고, `AI 설명`은 원문 위치를 연결한 실제 AI 요청입니다.
- 중요·개념/정의·외울 것·질문·이해 필요는 기존 PDF 주석 색상과 호환되는 PageDock 공부 의미입니다. `이해 필요`와 `질문`은 사용자가 직접 `이해 완료`로 바꿀 때까지 미해결로 남습니다. 읽는 순간의 행동은 `이해 필요`이고, Library와 기록 목록에서는 같은 미해결 항목을 `다시 볼 것`으로 보여 줍니다.
- AI 설명은 선택한 PDF·페이지·문장 위치에 연결됩니다. 대화의 `p.N · 선택 영역` 표시를 누르면 원문으로 돌아가며, PDF를 다시 열면 해당 위치에 작은 대화 표시가 나타납니다.
- 선택 원문에 연결된 AI 답변에서는 `다른 관점 보기`로 DeepSeek 웹에 같은 발췌와 질문을 직접 확인할 수 있습니다. PageDock은 내용을 자동 전송하거나 DeepSeek 웹 답변을 읽지 않습니다. 사용자가 직접 복사·전송하고 답변을 붙여넣으면, 현재 대화 안에서 두 답변을 나란히 비교합니다. DeepSeek 웹 로그인 정보는 별도 웹 세션에만 남으며 PageDock은 비밀번호·쿠키·토큰을 읽거나 백업하지 않습니다.
- 하이라이트와 AI 답변은 `지식 후보로 보내기`로 기존 Knowledge 수집함에 보낼 수 있습니다. `문헌 주장`·`업무 관찰`·`개인 가설`·`AI 추론` 중 출처 유형을 직접 확인하며, 원문 앵커와 등록일을 보존합니다. 이는 진실 판정이나 자동 위키 반영이 아닙니다.
- 선택 문장이나 원문 위치가 있는 AI 답변은 직접 편집 가능한 복습 카드로 저장할 수 있습니다. PDF 선택문에서는 원문의 짧은 한 구를 직접 가린 빈칸 카드도 만들 수 있습니다. 현재 PDF의 `오늘 복습`에서 답을 가린 뒤 `다시`(내일) 또는 `기억함`(3일 뒤)을 표시하고 언제든 정확한 원문으로 돌아갑니다.
- Reader의 `기록 보기`는 문서 도구 더보기에서 열며, PDF 너비나 위치를 바꾸지 않는 오른쪽 오버레이 서랍입니다. `읽기` / `업무` / `영역`에서 같은 원문으로 바로 돌아갑니다. 이해 필요를 새로 저장하면 조용한 `다시 볼 것 보기` 링크로 해당 필터를 곧바로 열 수 있습니다. 업무 관련 PDF라면 `더보기`의 업무 후속에서 `Finding`(우리 업무에 주는 의미), `Verify`(추가 확인), `Discuss`(회의 논의), `Try`(검토·실험)를 원문 하이라이트에 붙일 수 있습니다. 기존 하이라이트 기록에서도 footer의 `AI에게 묻기`로 다시 질문할 수 있습니다.
- Reader의 `영역 기록`으로 그림·표·수식·공정 조건을 사각형으로 지정해 종류와 메모를 남길 수 있습니다. 드래그 직후 원문 가까이에 작은 기록 창이 열립니다. 이미지 crop이나 AI 해석을 따로 저장하지 않아도, `기록`의 영역 목록에서 원본 PDF의 정확한 영역으로 다시 돌아갑니다.
- 내보내기 메뉴의 `업무 Evidence Brief`는 현재 PDF의 Finding·열린/완료 업무 후속을 구조화해서 보고 Markdown으로 내보냅니다. 이해 필요 항목은 화면에서만 보조 맥락으로 표시되며 다운로드 Markdown에는 포함되지 않습니다.
- 라이브러리 상단의 `계속 읽기` 카드는 가장 최근 문서 하나에만 `이어서 읽기`를 주 행동으로 둡니다. `다시 볼 것 N`은 작은 보조 링크이며, 누르면 그 PDF의 기존 미해결 기록 drawer만 엽니다. 문서 행도 가능한 경우 `p.N에서 이어 읽기 · 다시 볼 것 N · 업무 열림 N`을 보여 줍니다. 이 요약은 기존 metadata와 sidecar에서만 계산합니다.
- 마지막 읽은 페이지와 스크롤 위치는 휴대 가능한 metadata에 저장됩니다. 기존 브라우저 localStorage 페이지 기록도 호환 fallback으로 유지합니다.
- AI와 Python/PyMuPDF는 선택 사항입니다. AI 연결이나 PDF 원본 주석 반영이 없어도 selection 표시, 미해결 관리, 메모, 이어읽기는 PageDock sidecar에 저장됩니다.

## 리서치와 AI

상단의 **리서치**에서 프로젝트를 만들고, 내 PDF 전문검색과 Crossref/OpenAlex 논문 검색, 특허번호·URL·PDF 추가를 사용할 수 있습니다. 공개 PDF는 사용자가 승인해야 라이브러리로 복사됩니다. 유료 원문 우회 기능은 제공하지 않습니다.

Codex 정밀분석은 사용자가 선택한 자료만 분석하며 원문 근거, 도면 해석, 기술적 추정, 불확실을 구분합니다. AI 연결이 없어도 PDF 읽기와 일반 전문검색은 동작합니다. Knowledge의 `재검토 표시`는 사용자가 직접 지정할 때만 생기며, 오래된 문헌이라는 이유만으로 지식을 자동 폐기하거나 오류로 표시하지 않습니다.

## AI 모델과 업데이트

모델 선택기의 **자동 (Codex 권장 모델)** 은 모델 ID를 고정하지 않습니다. Codex가 계정과 설치 버전에 맞는 권장 모델을 선택하므로 후속 모델이 제공되어도 PageDock 소스를 수정할 필요가 없습니다. OpenCodex 계정 연결 방식에서는 인증된 모델 목록에서 권장 모델을 확인합니다.

PageDock은 실행 후 GitHub Releases에서 새 버전을 확인합니다. 업데이트가 있으면 사용자 동의를 받은 뒤 백그라운드에서 받고, 재시작 또는 앱 종료 시 설치합니다. PDF와 공부 기록은 업데이트 대상에 포함되지 않습니다.

Codex 자체는 설정 화면의 **업데이트** 버튼으로 공식 최신 안정 버전을 준비할 수 있습니다.

## 개발

요구 사항:

- Node.js 24 이상
- npm
- Windows 10/11 x64 데스크톱 빌드 환경

```powershell
npm install
npm run dev
```

Electron 개발 창과 Next.js 개발 서버를 함께 실행하려면:

```powershell
npm run dev:desktop
```

정적 검사와 웹 빌드, 아이콘 생성을 한 번에 확인하려면:

```powershell
npm run verify:release
```

Windows 설치 파일을 로컬에서 만들려면:

```powershell
npm run build:desktop
```

결과물은 `dist\PageDock-Setup-버전.exe`에 생성됩니다.

## 새 버전 배포

애플리케이션 버전의 단일 기준은 `package.json`입니다. 백업 설명 파일과 Electron 설치 파일도 이 버전을 사용합니다.

```powershell
npm version patch
git push origin main --follow-tags
```

`v*` 태그가 GitHub에 올라오면 `.github/workflows/release.yml`이 Windows 설치 파일과 자동 업데이트 메타데이터를 검사·빌드해 공개 `PageDock-Releases` 저장소에 게시합니다. 비공개 소스 저장소에는 해당 공개 저장소에 쓸 수 있는 `PAGEDOCK_RELEASE_TOKEN` secret이 필요합니다. 기능 추가는 `minor`, 호환되지 않는 변경은 `major` 버전을 사용합니다.

초기 지인 테스트 이후 공개 배포 전에는 Windows 코드 서명 인증서를 연결해 SmartScreen 경고를 줄여야 합니다.

## 환경 변수

- `PAGEDOCK_ROOT`: 라이브러리 경로 강제 지정
- `PAGEDOCK_PYTHON_BIN`: Python 실행 파일 경로 지정
- `CODEX_BIN`: Codex 실행 파일 경로 지정

기존 `ANNOT_ROOT`, `ANNOT_PYTHON_BIN`도 이전 사용자 호환을 위해 계속 인식합니다.
